> Goal: a Rust project that decrypts a flag it is already carrying, and refuses to compile. Three lines are wrong on purpose.

## Approach

Rust is not on the box by default, so the toolchain comes first. `rustup` installs the compiler and Cargo, its build tool and package manager, and `source` puts them on the path for the current shell without opening a new one.

```bash frame="code" title="Bash"
┌──(Idan@Kali)-[~/Rust_fixme_1]
└─> curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
┌──(Idan@Kali)-[~/Rust_fixme_1]
└─> source $HOME/.cargo/env
┌──(Idan@Kali)-[~/Rust_fixme_1]
└─> tar -xzf fixme1.tar.gz
```

`src/main.rs` turns out to be finished. It holds a key, 33 encrypted bytes as hex strings, and a call into the `xor_cryptor` crate that turns one into the other. There is nothing to reverse and nothing to work out. It simply does not build, and the three faults each come with a comment naming the question you have to answer.

```rust frame="code" title="src/main.rs, as shipped"
let key = String::from("CSUCKS") // How do we end statements in Rust?

    ret; // How do we return in rust?

println!(
    ":?", // How do we print out a variable in the println function?
    String::from_utf8_lossy(&decrypted_buffer)
);
```

Three tokens fix all of it: a `;` after the key, `ret` becomes `return`, and `":?"` becomes `"{}"`. The last one is the only one that is not purely mechanical, since `{}` is the placeholder `println!` substitutes an argument into, and `:?` on its own is neither a placeholder nor valid inside one.

## Why it works

The challenge is not really about Rust, it is about reading what the compiler tells you. Each of the three faults is a different phase complaining: a missing semicolon is caught while parsing, `ret` is an unresolved name, and the format string fails while the macro expands. That is also why they surface one or two at a time rather than all at once, and why the loop is build, read the message, fix, build again. `rustc` names the file, the line and usually the repair, which makes the compiler the walkthrough rather than an obstacle in front of it.

The decryption never needed attention, but it is worth not describing it wrongly. `xor_cryptor` XORs the buffer against a stream derived from the key and then pushes the result through a fixed substitution table, so it is XOR based without being a one line XOR. The recorded bytes prove that on their own: four of the 33 have their top bit set, while both the key and the flag are plain ASCII, and exclusive-or of two seven bit values can never produce an eighth.
